## Database > RDS for PostgreSQL > DBエンジン { #database-rds-for-postgresql-db-engine }

<a id="db-engine"></a>
## DBエンジン { #db-engine }
PostgreSQLのバージョン番号は `X.Y` 形式で構成されます。NHN CloudのRDS for PostgreSQLで `X` はメジャーバージョン、 `Y` はマイナーバージョンを表します。

<a id="db-engine-version-provided-by-rds"></a>
### RDSが提供するDBエンジンのバージョン { #db-engine-version-provided-by-rds }

下記のバージョンを使用できます。


| バージョン            | 備考 |
|---------------------|-------------------------------|
| <strong>17</strong> |                               |
| PostgreSQL 17.10    |                               |
| PostgreSQL 17.6     |                               |
| PostgreSQL 17.4     |                               |
| PostgreSQL 17.2     | 新規に作成したり、Read Replica を追加したりすることはできません。 |
| <strong>14</strong> |                               |
| PostgreSQL 14.23    |                               |
| PostgreSQL 14.19    |                               |
| PostgreSQL 14.17    |                               |
| PostgreSQL 14.15    | 新規に作成したり、Read Replica を追加することはできません。 |
| PostgreSQL 14.6     | 新規に作成したり、Read Replica を追加したりすることはできません。 |

!!! warning "注意"
    PostgreSQL 14.6、14.15、17.2 バージョンは、最新バージョンへのアップグレードを[推奨](https://www.postgresql.org/support/security/CVE-2025-1094/)します。

<a id="perform-version-upgrades"></a>
### バージョンアップグレードを実行する { #perform-version-upgrades }

バージョンアップグレードは順次行われ、メジャーバージョンアップグレードとマイナーバージョンアップグレードのそれぞれの特性によって異なる順序で行われることがあります。

バージョンアップグレードを行う前に、データ損失防止のため、バックアップを行うことを推奨します。

<a id="perform-version-upgrades-major-version-upgrade"></a>
#### メジャーバージョンアップグレード

メジャーバージョンアップグレードは、バージョン番号の最初の桁を変更することを意味します。例えば、14.6から17.2にアップグレードすることがメジャーバージョンアップグレードです。

RDS for PostgreSQL では、メジャーバージョンアップグレードは Primary でのみ実行できます。実行すると、DBインスタンスグループ内のすべてのDBインスタンスのバージョンをアップグレードします。

<a id="perform-version-upgrades-major-version-upgrade-order"></a>
#### メジャーバージョンアップグレードの順序

Primary DB インスタンスを変更して、メジャーバージョンアップグレードを実行できます。
実行手順は次のとおりです。

- Primary DBインスタンスでバージョンアップグレードの事前チェックを実行します。
    - 事前チェックの結果に問題がなければ、バージョンをアップグレードします。
    - 事前チェックの結果はログファイル形式で提供され、DBインスタンス詳細の **[ログ]** タブで `pg_upgrade.log` ファイルから確認できます。
- DBインスタンスグループ内にPrimaryのみが存在する場合、Primary DBインスタンスのバージョンをアップグレードします。
    - バージョンアップグレード中はダウンタイムが発生します。
    - 失敗した場合、復旧作業が試行される場合があります。復旧に成功すると、バージョンアップグレード前の状態に戻ります。
    - 復旧作業にも失敗した場合、再構築で復旧を試みることができます。
- Primary以外のレプリケーション関係にあるDBインスタンス（Standbyを含む）の中からDBインスタンスを1つ選定して進めます。
    - 選定したDBインスタンスのバージョンをアップグレードします。
        - Standbyがある場合、Read Replicaより優先してバージョンをアップグレードします。
        - バージョンアップグレードに失敗した場合、他のDBインスタンスに対してはバージョンアップグレードを進めず、失敗したDBインスタンスは再構築作業で復旧を試みることができます。
    - アップグレードが完了したDBインスタンスの種別をPrimaryに変更し、グループ内の残りのDBインスタンスをアップグレードしてレプリケーション関係を再設定します。
        - 接続アドレスは変更されないため、既存の接続アドレスで接続できます。
        - バージョンアップグレード中はRead Replicaにダウンタイムが発生します。
        - バージョンアップグレード中に失敗した場合、レプリケーションが中断された状態のまま維持され、再構築作業で復旧を試みることができます。

!!! warning "注意"
    Primary 以外のレプリケーション関係にある DB インスタンスをアップグレードする段階では、Primary への書き込み負荷はブロックされ、読み取り負荷のみ処理できます。
    DB インスタンスグループ内に、バージョンアップグレードが成功した DB インスタンスと失敗した DB インスタンスが混在する場合があります。失敗した DB インスタンスはレプリケーション関係が中断され、再構築作業で復旧を試みることができます。

<a id="perform-version-upgrades-miner-version-upgrade"></a>
#### マイナーバージョンアップグレード

マイナーバージョンアップグレードは、バージョン番号の2桁目を変更することを意味します。例えば、14.6から14.15にアップグレードすることがマイナーバージョンアップグレードです。

RDS for PostgreSQL では、マイナーバージョンアップグレードは Primary だけでなく Read Replica でも実行できます。実行すると、対象の DB インスタンスのバージョンがアップグレードされます。高可用性構成が完了している Primary は、Standby も同時にアップグレードします。

<a id="perform-version-upgrades-minor-version-upgrade-order"></a>
#### マイナーバージョンアップグレード順序

- Primaryのバージョンアップグレードを試みる際にStandbyが存在する場合、一緒にバージョンをアップグレードします。
    - Primary単独でバージョンアップグレードが進行する場合、ダウンタイムが発生します。
    - Standbyとともにバージョンアップグレードが進行する場合、過程中にフェイルオーバーを利用した再起動が伴い、瞬断が発生する場合があります。
- Read Replicaのバージョンをアップグレードする際は、該当のDBインスタンス単独でバージョンをアップグレードします。
    - バージョンアップグレード中はダウンタイムが発生します。
    - 失敗した場合、復旧作業が試みられる場合があります。復旧に成功した場合、バージョンアップグレード前の状態に戻ります。
    - 復旧作業にも失敗した場合、再構築による復旧を試みることができます。
